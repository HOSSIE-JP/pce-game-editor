# PCE / Super CD-ROM2 メモリバンク運用ルール

このメモは、PCE Game Editor の CD-ROM2 / VN runtime で使う HuC6280 MPR と llvm-mos section の割り当てを固定化するための引き継ぎルールです。

## 基本方針

- CD-ROM2 build では、背景 tiles/map、sprite pattern、ADPCM 本体、PSG pattern のような大きい payload はまず `cd.dataFiles` に並べます。`cache load bg/sprite` は低位 System Card RAM の visual payload cache へ明示 asset を先読みし、表示 command は cache hit なら RAM→VRAM/BAT、miss なら従来どおり `cd_transfer_scratch` 経由で CD→VRAM/BAT へ転送します。ADPCM は ADPCM RAM へ読み込んで buffered direct playback し、`cache load psg` は bank134/135 の単一 PSG pattern buffer へ送ります。
- CPU が頻繁に読む小さい runtime data だけを RAM bank に置きます。表示 asset の実体は CD data file 優先です。
- `cd.dataFiles` は sector 64 以降に並ぶ前提で generated metadata に sector を埋め込みます。build は IPL program の後ろへ padding file を挟み、ISO 上の最初の data file が sector 64 から始まるようにします。padding サイズは固定ではなく、ELF build 後に `pce-mkcd -v` でプログラム像の実セクタ数を測定して `64 - program終端sector` で決めます（`finalizePceCdDataPadding()` / `parseMkcdFirstDataSector()`）。**RAM bank の配置やデータ量を変えて program 像のサイズが変わると、固定 padding では data 開始 sector がずれ、埋め込み済みの sector 参照（`pce_vn_font_data` / `pce_vn_scene_packs[]` / asset の `cd_data_ref`）が全部ずれて全画面が壊れます。** font tiles の CD streaming 化のように program サイズに影響する変更をしたら、必ず実 ISO で data 開始 sector が 64 のままか確認してください。
- VN runtime は `template/template_pce_vn_cd/src/pce_vn_runtime.c` が単一の実体です。project 側へ同期されるので、bank ルール変更は必ず template を直します。

## CD-ROM2 RAM Bank Map

| Bank | MPR | 主用途 | ルール |
|---:|---:|---|---|
| 128 | 2 | llvm-mos 既定の常駐 `.text` / `.rodata` | 起動・薄い制御・小さい rodata 用。大きい runtime や asset を押し込まない。CD BIOS や VN data access 後に常駐 metadata を読む場合は `map_resident_data()` で戻す |
| 129 | 3 | VN runtime の banked code | `PCE_RAM_BANK_AT(129, 3)` と `VN_BANKED_CODE` で command interpreter / VBlank wait / ADPCM の薄い入口・stop/wait、scene pack cache load の中核を置く。asset data を置かない。meta on-demand では `execute_command()` を bank129 の out-of-line 関数に保ち、sprite descriptor の hot field は snapshot して使う |
| 104-119 | 6 | VN visual payload RAM cache（実験版） | `VN_ENABLE_VISUAL_PAYLOAD_CACHE 1` のとき、8KB x 16 page = 128KB の LRU payload cache として使う。BG tiles、BG map、sprite patterns を `{kind, assetIndex, part}` key で保持する。visual cache の miss-fill は page を MPR6 に map し、CD BIOS から最大4 sectorを直接その page へ読む。CD→VRAM fallback も LRU page を一時 scratch として借り、最大4 sector read 後に RAM→VRAM へ sliced copy する。evict / clear は metadata だけを無効化し、VRAM/BAT/SATB/表示状態は触らない |
| 120 | 6 | 予備 | visual cache payload には使わない。bank121 helper code と隣接させないため、標準 runtime では未使用 |
| 121 | 4 | VN visual cache helper code | `PCE_RAM_BANK_AT(121, 4)`。`visual_code.bin` を CD から CPU 0x8000 へ読み込み、`cache load bg/sprite` の低位RAM操作、sprite animation tick、Cache Load Sprite の軽量 helper、CD-DA の play/stop command など、bank128/129/130 を圧迫しやすい slot4 helper を entry op 経由で実行する。bank133 Path B overlay / bank122 CD async helper とは別物で、互いに上書きしない。payload page としては使わない |
| 122 | 4 | VN direct CD/SCSI async helper code | `PCE_RAM_BANK_AT(122, 4)`。`cd_async_code.bin` を CD から CPU 0x8000 へ読み込み、System Card BIOS を使わない低レベル READ(6) / SCSI DATA IN service を entry op 経由で実行する。Phase 2 では scene pack cache の CPU RAM read をこの path に接続し、loading frame は `vn_wait_next_vblank_raw()` → `engine_service()` → `vn_cd_async_service_frame()` とする。async data phase 中は `quiet_cd_unit_irqs()` を呼ばず、TIMER は runtime 所有のまま。bank130 / bank121 / bank133 と slot4 を時分割するため、dispatcher は bank129、実 core は bank122 に置く |
| 123-127 | - | 予備 | 標準 runtime では未使用。visual cache payload の拡張に使う場合も bank121 code と bank122 CD async code との分離を保つ |
| 130 | 4 | VN runtime の 2 本目の banked code | `PCE_RAM_BANK_AT(130, 4)` と `VN_BANKED_CODE2` で scene pack choice/switch reader、preload scan helper、raw BG map の行単位 CD 転送、Choice UI helper、PSG sequencer helper、CD-DA Audio command の薄い dispatch、sprite animation cache helper、ADPCM load/play 本体と buffer-fit helper、`PCE_VN_COMMAND_CACHE load` の協調状態機械を置く。asset data を置かない。message グリフコンポジタは Phase 2 で bank133 overlay へ退避済み。Effect の fade/flash palette 補間本体と CD-DA play/stop 本体は bank130 圧迫を避けるため visual code bank121 へ置き、bank130 には dispatch wrapper だけを残す |
| 131 | 5 | CD fallback の小さい CPU-readable data | 例外的な fallback 用。通常の画像・sprite・ADPCM payload には使わない。**コードは置けない**（System Card/CD-BIOS が slot5=0xA000 で実行されるため physical bank131 にコードを置くと暴走する） |
| 132 | 6 | VN generated data ＋ CD転送スクラッチ | `PCE_VN_DATA_SECTION`。sprite animation、variable 初期値、scene pack directory、font tiles の CD data ref (`pce_vn_font_data`) を置く。**font tiles 本体は bank132 に常駐させず CD data file (`assets/generated/vn/font.bin`) からストリーム**。scene script 本体も CD data file。font streaming で空いた領域に **`cd_transfer_scratch`(2KB) を `section(".ram_bank132")` で移設**し、逼迫する console_ram を空ける。CD-ROM2 VN の BG / Sprite / ADPCM / PSG / CD-DA metadata は常に asset catalog (`assets/generated/meta/asset_meta.bin`) へ置き、bank132 常駐は `pce_editor_*_meta` の sector/count/slot だけにする。短い PSG SFX も含めて pattern を CD data file (`assets/generated/psg/<id>.bin`) として扱い、再生時に bank134/bank135 へ展開する。末尾 0xd078-0xdfff はオーバーレイ blob の良性 LMA に使用する（下記）。**固定バッファ `cd_transfer_scratch`(2KB)/`message_glyph_cache_masks`(1632B)/BG descriptor cache palette storage(256B) は `.ram_bank132_tail`(NOLOAD) としてこの良性 LMA window に重ね、読まれない overlay コピーの RAM を再利用する**ので、asset metadata は件数に比例して bank132 を圧迫しない |
| 134 | 6 | 再生中の PSG 曲パターンバッファ前半。bank132 と slot6 を時分割 | IPL 非ロード。`play_psg_asset()` が `load_psg_pattern_cd()` で現在再生中の step pattern 前半を CD から bank134 RAM へ読み込み、`psg_apply_step_row()` は読む前に `pce_ram_bank134_map()` で MPR6=bank134 を張る。8byte/entry で 1024 event まで収容。System Card 非干渉 |
| 135 | 6 | 再生中の PSG 曲パターンバッファ後半。bank132/bank134 と slot6 を時分割 | IPL 非ロード。pattern が 1024 event を超える場合だけ `load_psg_pattern_cd()` が後半を bank135 RAM へ読み込み、`psg_apply_step_row()` が `pce_ram_bank135_map()` で後半を走査する。bank134+135 合計 16KB、最大 2048 event。曲数無制限（同時に RAM に載るのは 1 曲） |
| 133 | 4 | コードオーバーレイ（Path B、Phase 3 で **物理 8KB フル**化）。bank130 / bank121 と slot4 を時分割 | IPL は bank128-132 しか自動ロードしないため bank133 は CD data file (`assets/generated/vn/overlay.bin`、予約 4 sector=8KB) からブート時に `pce_cdb_cd_read` で CPU 0x8000 へ 8KB ストリーム。`VN_OVERLAY_CODE` タグの関数を置き、**単一固定エントリ `vn_overlay_entry`(`.vn_overlay.entry`) への literal 0x8000 間接呼び**で reloc を消して section を ELF から除去（良性 LMA 不要）。現行 runtime は message グリフコンポジタ・sprite frame・scene_pack decoder/range check・cache_sprite_animation・cdda_sector_from_remaining・ADPCM voice snapshot copy 等を置く。System Card 非干渉（bank131 と違い安全） |
Visual payload cache は低位 RAM 利用の実験版として標準有効です。`visual_code.bin` / `.vn_visual_code` は bank121 専用、payload は bank104-119 専用とし、旧案のように同じ bank を code と payload page で共有しません。`visual_code.bin` は boot 時に読み込み、bank128/129 側の resident dispatcher から entry op 経由で呼びます。`cd_async_code.bin` / `.vn_cd_async_code` は bank122 専用で、scene pack cache の direct SCSI read から使います。どちらも抽出後の main ELF では section と対応 `PT_LOAD` program header を `neutralizeElfLoadSegments()` で無効化します。section を消すだけでは `pce-mkcd` の初期ロード表に helper が残り、System Card boot が `JUST A MOMENT...` で止まることがあります。main ELF から `.vn_visual_code` / `.vn_cd_async_code` は除去されるため、bank128/129/130 から該当関数へ直接 relocation を残さず、必ず fixed-address entry op 経由にしてください。切り戻しが必要な場合は `VN_ENABLE_VISUAL_PAYLOAD_CACHE` や direct async 使用箇所を戻す形で、command record や JSON schema は維持します。bank128/129/130 はまだ薄い余白しかないため、新しい helper を追加する前に既存 code path の削減、`VN_BANKED_CODE` / `VN_BANKED_CODE2` / `VN_OVERLAY_CODE` / `VN_CD_ASYNC_CODE` の付け替えを検討し、必ず `mos-pce-cd-clang -Wl,--print-memory-usage` か `llvm-size -A` で再確認してください。

## コードオーバーレイ（Path B / Phase B1）

3 つの常駐コードバンク（128/129/130 ＝計約24KB）を超えるエンジンコードを、未使用の物理 bank133 へ退避してブート時に CD からロードし、bank130 と MPR slot4 を時分割する機構。**追加・拡張の具体手順、検証手順、残課題は専用の引き継ぎガイド [pce-vn-overlay-pathb.md](pce-vn-overlay-pathb.md) を参照。**

- **配置タグ**: `pce_vn_runtime.c` で `VN_OVERLAY_CODE`（CD build では `__attribute__((noinline, section(".vn_overlay")))`、非 CD では空）。エントリは `VN_OVERLAY_ENTRY_CODE`(`.vn_overlay.entry`)。Phase B1 は CD RLE 展開を、Phase 2 は message グリフコンポジタを退避。**Phase 3 で op-dispatch 化し full 8KB へ解放**、scene_pack decoder / cache_sprite_animation / cdda_sector_from_remaining / message_glyph_cache_find 等の純粋関数も退避（co-residency 上 `delay_frame`/bank130/visual_cache を呼ぶ関数は退避不可）。per-frame sprite 差分 refresh は VBlank 同期のため bank130 に戻した。**退避先は overlay(bank133) / bank121(visual-code) / bank122(CD async-code) の slot4 リザーバ**。詳細手順は [pce-vn-overlay-pathb.md](pce-vn-overlay-pathb.md)。
- **同一コンパイル**: オーバーレイは本体と同じ link に含めるため、llvm-mos の zero-page 仮想レジスタや常駐シンボルがそのまま解決される（B0 の別リンク方式が抱えた `R_MOS_ADDR8 out of range` 等の壁を回避）。
- **リンカ fragment**: `pce-vn-manager.js` が `src/generated/overlay_insert.ld`（`INSERT AFTER .ram_bank132`）を生成し、`-Wl,-T` で本体 link に差し込む。Phase 3 では `.vn_overlay 0x1858000 : { KEEP(.vn_overlay.entry) KEEP(.vn_overlay ...) } >ram_bank133` で **独自 load 領域 ram_bank133**（VMA `VN_OVERLAY_LINK_ADDR`、低16bit=0x8000 で CPU 0x8000 実行）に置く（旧 `AT(bank132末尾 LMA)` は撤去）。同 fragment の `.ram_bank132_tail 0xd078 (NOLOAD)` は write-before-read の固定バッファ（`cd_transfer_scratch`/`message_glyph_cache_masks`/BG palette）を bank132 末尾に置くだけで、もう overlay と重ならない（overlay は bank133）。メタデータ予算 [0xc000, 0xd078) は不変。大きい PSG パターンは bank132 ではなく bank134 へ CD ストリーム。
- **抽出と mkcd 回避**: link 後に `llvm-objcopy --only-section=.vn_overlay` で `overlay.bin` を抽出（予約 4 sector=8KB に pad）し、`--remove-section=.rela.vn_overlay` ＋ `--remove-section=.vn_overlay` で **reloc テーブルと section 本体を ELF から除去**（visual-code と同方式。op-dispatch で resident→overlay の reloc が無いので本体ごと消せる）。さらに `neutralizeElfLoadSegments()` で ram_bank133 の `PT_LOAD` を `PT_NULL` 化（pce-mkcd は program header も参照するため、残すと初期ロード像に bank133 が混ざり System Card boot が止まりうる）。pce-mkcd は ELF の relocation を再適用するため、0x8000 VMA を持つ overlay 内部 reloc を残すと `File address 0x8001 out of range` で失敗する。lld が既に適用済みなので `overlay.bin` は完成形。Windows の objcopy 解決・Defender レース対策（temp+rename, 非空検査）は visual-code 経路と共通。
- **CD sector 予約**: `overlay.bin` のサイズは link 前に固定予約（`VN_OVERLAY_RESERVED_SECTORS`）して `generateVnSources` が CD sector を確定し、link 後に実バイトで同サイズ上書きするので sector がずれない。実コードが予約を超えると build error。
- **ランタイム dispatch**: 常駐 bank128/129 の dispatcher が **bank133 を slot4 に map → `((fn)0x8000)(op,a0,a1,a2)` 間接呼び（`vn_overlay_entry` が op 分岐）→ bank130 を復帰**する。VDC を触る関数と、PSG step 適用のように PSG MMIO / MPR6(bank134/135) を触る関数は `vn_overlay_dispatch_locked`（**IRQ lock → bank133 map → overlay → bank130 restore → IRQ unlock**）、純粋な scene-pack read は `vn_overlay_dispatch`（IRQ ロック無し）。**slot4 を共有する bank130/bank133/bank121 間の直接相互呼び出しは禁止**（オーバーレイ実行中は bank130/bank121 が見えない）。オーバーレイ関数は slot2/slot3（bank128/129）・inline/`map_vn_data`(slot6)・console_ram・CD BIOS のみ呼ぶ（**`delay_frame` は bank130 map を含むため不可**）。dispatcher は bank128/129 に置く（bank130 不可）。退避前検証は `-Wl,--emit-relocs` で link した elf を `llvm-objdump -dr --section=.vn_overlay` し、reloc が `.ram_bank130+`/`.ram_bank121+` を指さない（`.vn_overlay`/`.text` のみ）ことを確認。
- **オーバーレイサイズ上限**: 物理 bank133 = 8KB。`finalizeOverlayBlob()` が `realSize > VN_OVERLAY_RESERVED_BYTES`(=8192) を検査し、超える場合は明示エラー（bank121 visual-code への分散か runtime 削減を促す）。CD 上の予約 `VN_OVERLAY_RESERVED_SECTORS`(=4) を変えると後続 CD data file の sector が一律ずれる（IPL padding が data 開始を sector 64 に保つので埋め込み sector 参照は整合）。

## 実装ルール

- `ram_bank129` は起動時に `pce_ram_bank129_map()` で MPR3 へ常時 map します。`VN_BANKED_CODE` 関数はこの前提で直接呼びます。ADPCM は入口・stop/wait など bank130 呼び出し側からも必要な薄い処理だけ bank129 に残し、load/play 本体は bank130 へ寄せます。bank129 は command loop / ADPCM / sprite refresh で膨らみやすいため、PSG の細かい helper や Effect の palette 補間、Choice/IF/Switch/Goto を含む command execution 本体など、bank130 から呼んでも問題ない処理を戻さないでください。meta on-demand では accessor 戻りポインタ由来の field load が大きくなりやすいので、`vn_get_*_asset()` はループ/関数入口で 1 回だけ呼び、必要 field を slot-local draw metadata、data ref、cell map pointer、snapshot state へ落としてから使います。
- `ram_bank130` も起動時に `pce_ram_bank130_map()` で MPR4 へ常時 map します。`VN_BANKED_CODE2` は bank129 に収まらない scene pack reader / preload helper / PSG helper / Effect palette helper / Choice UI helper / command execution helper / ADPCM load/play 本体用で、MPR4 を asset fallback に切り替えない前提です。Choice/Variable/IF/Switch/Goto/Label/InputCheck を扱う `execute_control_command()`、`draw_choice_options()`、`jump_to_command()` は `VN_BANKED_CODE2` の noinline 関数として保ち、分岐処理や Choice UI が `run_commands_until_wait()` / bank128 `.text` へインライン展開されて各 bank を再び溢れさせないようにします。`draw_choice_options()` から message glyph を描く場合は resident dispatcher `call_overlay_draw_message_glyph_at()` 経由で bank133 overlay を呼びます。CD-DA を Audio command から使う project では CD-DA play/stop だけでも bank128/130 が太るため、本体は `VN_VISUAL_CACHE_OP_CDDA_COMMAND` として bank121 visual-code 側に置き、bank130 には小さい command wrapper だけを残します。CD-DA は data read と同じ CD drive を使うため、ロード中の継続再生はできません。現行既定では `VN_CDDA_RESUME_AFTER_DATA_READ 0` とし、CD data read 前にCD-DAをpauseして停止扱いにしますが、自動resume管理は常駐 bank へ載せません。CD load と共存させる BGM には PSG を使う前提です。
- ADPCM asset metadata を runtime snapshot へコピーする `copy_adpcm_voice_impl()` は bank133 overlay に置き、bank129 には `VN_OVERLAY_OP_COPY_ADPCM_VOICE` dispatcher wrapper だけを残します。ADPCM load/play は bank130 からこの wrapper を呼ぶため、overlay 実行中に bank130/121 を直接呼ばない契約を守ってください。
- `ram_bank128` の常駐 data を読む runtime code は、CD BIOS helper や `map_vn_data()` 呼び出し後に `map_resident_data()` を挟んでから参照します。CD-ROM2 VN では、ジェネレータが BG / Sprite / ADPCM / PSG / CD-DA metadata を常に CD data file `asset_meta.bin` へ置き、ランタイムの `vn_get_*_asset` accessor がオンデマンドでストリームします（[pce-asset-meta-cd-ondemand.md](pce-asset-meta-cd-ondemand.md)）。RAM 常駐は各種別の `pce_editor_*_meta` sector/count/slot と asset count だけにし、asset 数に対して O(1) に保ちます。HuCard や非 VN CD template が使う resident asset 配列は別 runtime 用です。`pce_editor_*_asset_count` と `pce_editor_meta_region_t.count` は `unsigned int` です。runtime では scene command の signed index を `0..count-1` で検証してから使い、`(uint8_t)asset_index` 比較へ戻さないでください。
- runtime state の非ゼロ初期値は `.data` / `.zp.data` として bank128 の load 領域も消費します。`ui_text_color`、InputCheck の target など、`init_runtime_state()` や scene 入場で必ず初期化する値は BSS に置き、`= PCE_VN_NO_COMMAND` のような static initializer を戻さないでください。数 byte でも bank128 overflow の原因になります。
- 生成済み C metadata は scene 生成時に asset ID を index へ解決済みで、runtime では ID 文字列を使いません。`pce_editor_psg_asset_t` / `pce_editor_adpcm_asset_t` / `pce_editor_cdda_asset_t` に `id` field を戻すと bank128 の `.rodata` を直接圧迫するため、debug 用文字列は JSON 側に留めます。
- CD-ROM2 VN build では、`assets.c` に出す runtime asset metadata を scene command 参照済み asset に絞ります。未使用 BG/sprite/audio を `pce-assets.json` に残しても、scene から参照しない限り VRAM 排他予約・asset index・resident bank128 予算には入れません。asset index の整合性を保つため、`generateVnSources()` の index 作成と `generateAssetSources({ assetIds })` の filter は同じ asset ID set を使います。CD-DA track metadata も asset catalog に置き、runtime は command 実行時に必要な record だけを `cd_transfer_scratch` へ読むため、CD-DA用の resident asset cache は持ちません。
- `ram_bank132` を読む前は `pce_vn_font_tiles_map()` または runtime の `map_vn_data()` を呼びます。MPR6 を切り替えるため、MPR6 上で実行される code を作らないでください。**MPR6(slot6) は bank132（VN data / catalog scratch）、bank134/bank135（再生中 PSG パターン）が時分割で共有**します。bank132 を読む側は使用直前に必ず `map_vn_data()`、PSG パターンを読む `psg_apply_step_row()` は前半で `pce_ram_bank134_map()`、後半で `pce_ram_bank135_map()` を張ります。message window の全 BAT remap は `msg_bat_row` を埋める C ループから `write_map_words()` までを row 単位で IRQ lock します。BG/sprite/font/scene pack などの CD 転送待ち、RAM/CD→VRAM 転送、palette fade 中は `engine_service_blocking()` / `engine_service()` が cooperative に `psg_advance()` + `psg_commit()` を呼びます。CD read chunk は `VN_PSG_CD_TRANSFER_COMPENSATION_FRAMES` で PSG だけを明示補償し、ADPCM の再生残フレームは実 VBlank credit 由来の service だけで減らします。VRAM/BAT/表示待ち系の service は VDC の VBlank status をポーリングして実際に frame が進んだ時だけ credit を消費します。通常フレームは `delay_frame()` が VBlank 待ちを終えた直後に進め、display/sprite/message window の直接 VBlank 待ちも待ち直後に `engine_service()` で補います。PSG 再生中の BG/sprite VRAM copy は `VN_VISUAL_VRAM_COPY_SLICE_BYTES` ごとに分割して各 slice 後に service しますが、VBlank gate と credit cap により slice 数だけ PSG が早送りされることはありません。PSG が鳴っていない場合は `VN_VISUAL_VRAM_COPY_FAST_SLICE_BYTES`（1 sector）までまとめて TIA 転送します。PSG pattern を読むと MPR6 が bank134/bank135 へ変わるため、通常の blocking helper は最後に `map_vn_data()` で MPR6 を bank132 へ戻します。**slot4(MPR4) は「呼び出し時のバンクを保存して復元」が契約**です: `service_psg_advance()` / `service_adpcm_during_blocking_frames()` は入口で `vn_slot4_current_bank()` を保存し、出口で `vn_slot4_map_bank()` で復元します。この service は bank130 コードだけでなく **bank133 overlay（例: `refresh_scene_sprite_patterns_impl` → `upload_sprite_pattern_words`）や bank121 visual cache からも呼ばれる**ため、無条件に `VN_MAP_BANK130_FOR_CODE()` へ戻すと overlay/visual cache の呼び出し元が unmap され、RTS が別バンクのバイト列に落ちて I/O ページ実行の暴走（画面ごみ・PSG ノイズ連発・ADPCM 誤再生）になります（PSG SONG + ADPCM + sprite アニメ同時のときだけ service が実際にバンクを触るため、その組み合わせでのみ発症していました）。
- bank134/135 は PSG pattern の単一 buffer です。`Cache Load PSG` と banked PSG の再生開始は同じ buffer を使うため、現在の PSG が resident/small pattern の場合だけ現曲を鳴らしたまま次の banked pattern を先読みできます。現在の PSG も banked pattern の場合は bank134/135 が現曲そのものなので、`Cache Load PSG` は上書きせず skip し、`play_psg_asset()` も従来どおり stop -> load -> start に戻します。二重 buffer（bank136/137 など）は現行設計に含めません。
- 現行既定の `VN_TIME_SOURCE_TIMER 1` では、HuC6280 TIMER IRQ が通常フレームの実 credit を `vn_vblank_credit` に積みます。CD/ADPCM BIOS helper 中は System Card へ TIMER を返すため、`cd_transfer_wait()` / visual cache CD wait が VBlank edge の実測 credit に加えて `VN_PSG_CD_TRANSFER_COMPENSATION_FRAMES`（既定 `10u`）の PSG 専用 tick を即時適用します。この補償は `vn_vblank_credit` へ混ぜず、ADPCM 残り時間・message 同期・入力待ちを進めません。
- `cd_transfer_scratch`(1 sector=2KB) は `section(".ram_bank132")` に置き、CD→VRAM 転送ヘルパ（`cd_data_ref_to_vram` / `cd_bg_map_ref_to_vram` / `upload_font_tiles`）と visual cache の CD→低位RAM page 転送で使います。各ヘルパは asset/font の CD data ref を読む前に `map_vn_data()` で MPR6=bank132 を張り、CD read 完了後に CD-DA を再開してから RAM→VDC data port へ TIA 転送します。PSG 再生中だけ短い slice 単位で cooperative service を挟み、無音時は 1 sector までまとめて VRAM copy します。逆に **CD BIOS の書き込み先になる buffer や CD data ref を正しい MPR6 bank へ張らずに使うと、転送データや sector 参照が別バンクへ化けます**。`vn_active_scene_pack_data`(4KB) はコマンド解釈の各所から読むため console_ram に残します（bank132 へ移すなら全 reader で MPR6 を保証する必要があり要慎重）。
- グリフフォントは BG タイルと同じく `cd.dataFiles` の `assets/generated/vn/font.bin` に並べ、起動時に `upload_font_tiles()` が `cd_transfer_scratch` 経由で 1 回だけ VRAM (`PCE_VN_FONT_MASK_VRAM_WORD` から) へストリーム転送します。font.bin の中身は **12x12 1bpp マスク（12 word=24 byte/グリフ）**で、表示用の先焼きタイルではありません。CD runtime は message 開始時、ADPCM を鳴らす前にそのページの glyph mask だけを上限付き RAM cache へ先読みし、音声再生中の compositor は VRAM 読み戻しではなく cache を優先して 12px ピッチで合成します（cache 外 glyph だけ従来の VRAM 読みへ fallback）。合成時は tile と glyph の交差範囲だけを走査し、前 glyph が重ならない tile は即 return して、ADPCM 再生中の per-glyph CPU cost を抑えます。cache mask 本体は console RAM を圧迫しないよう `.ram_bank132` に置き、lookup 用 ID/count だけを `.bss` に残します。bank132 には sector/サイズだけを持つ `pce_vn_font_data` (`pce_vn_cd_data_ref_t`) を常駐させ、glyph 数に比例した数 KB を bank132 から外します。font.bin は `collectCdDataFiles()` で先頭 (CD sector 64) に置き、埋め込み sector と ISO 配置を一致させます。glyph index は 16bit エスケープ符号化（0..252 は 1 byte、253 以上は `0xfd`+16bit LE）で旧 254 種上限を超えられ、VRAM 側の上限だけが残ります。`generateVnSources()` の `computeFontBudget()` がマスク領域末尾 (SATB `0x7f00`)・VRAM tile soft ceiling をビルド時に検査し、超過は build error、接近は警告します（既定 `tileBase` で実用上限はおよそ 1000 種 = `VN_MAX_GLYPH_COUNT`）。マスク領域は固定 208 タイルのメッセージ帯＋blank tile の直後に置かれます。非 CD (`__PCE__`) build だけ従来通り `pce_vn_font_tiles[]`（中身はマスク）を埋め込みます。
- `spritetext` command を使う場合のみ、スプライト用フォント `assets/generated/vn/font_sprite.bin` を追加生成します（`spritetext` が実際に使う文字種だけを PCE スプライトパターン形式で encode）。font.bin と同じく `cd.dataFiles` に並べ、起動時に `upload_font_sprite_patterns()` が `cd_transfer_scratch` 経由で 1 回だけ **スプライト pattern VRAM (`PCE_VN_FONT_SPRITE_PATTERN_BASE`)** へストリームし、bank132 には `pce_vn_font_sprite_data` (sector/サイズ) だけ常駐させます。pattern base は BG グリフフォント直後（32-word pattern 単位）へ自動配置し、VN character sprite はそのさらに後ろの `PCE_VN_SPRITE_PATTERN_BASE` から連続配置します。spritetext font が SATB と重なる場合は `generateVnSources()` が warning を出します。色は予約 sprite palette bank `PCE_VN_FONT_SPRITE_PALETTE_BANK`（既定 15）の index15 を runtime が command ごとに書き換えて表現します。文字種ゼロ（spritetext 未使用）なら font_sprite.bin は生成せず、CD sector も予約しません。
- VN script は scene 単位の `assets/generated/vn/scenes/NNN_<sceneId>.bin` として `cd.dataFiles` に置きます。pack は pointer を持たない little-endian / offset ベース形式で、`pce_vn_scene_packs[]` だけを bank132 に常駐させます。
- runtime は scene 入場時に active scene cache (`4096` bytes) へ pack を読み込み、最初の `message` / `choice` / `wait` / `jump` までに必要な初期表示 asset だけを先読みします。別 scene 用の preload scan cache は持ちません。旧 `preload` command は廃止済みです。build は最初の `message.voiceAssetId` 用の内部 `Cache Load ADPCM` を、分岐やADPCM cache操作より前なら scene 先頭へ hoist し、PSG再生開始直前のADPCM RAM loadを避けます。以降のmessageで別ADPCMへ切り替わる場合は、そのmessage直前でADPCM RAMを読み替えます。ボタン待ち message の完了待機中には次の ADPCM cache load を先取りせず、次ページへ進んで command stream が再開した時点で通常の `cache load` として実行します。`cache` command の manual clear は BG/sprite/ADPCM/PSG/message glyph の runtime cache valid flag と visual payload cache metadata を落とすだけで、active scene pack cache や bank128/129/130/132/133 の code/data 配置とは別の制御です。`cache` command の manual load は scene pack を別途保持せず、command record に明示された単一 asset を対象にします。ADPCM は ADPCM RAM へ、BG/Sprite は bank104-119 の visual payload cache へ、PSG pattern は bank134/135 の単一 buffer へ読み込みます。scene丸ごとの別pack先読みや二重scene cacheではありません。pack が 4096 bytes を超える場合は build error にして scene 分割を促します。
- BG/Sprite の表示 command では、payload cache hit 時でも descriptor cache miss があると `asset_meta.bin` の小さな再読込だけで CD-DA が一瞬 pause します。そのため runtime は BG descriptor 8 枠、Sprite descriptor 4 枠の metadata cache を持ち、`cache load bg` は BG tiles/map payload だけでなく BG descriptor も温めます。BG descriptor cache は bank128/code容量を守るため asset index 下位3bitの direct-mapped 8枠で、palette byte storage だけ `.ram_bank132_tail` に置きます。BG 切替では現在表示中 BG の `map_base` / `width_tiles` / `height_tiles` を resident snapshot に保持し、旧 BG 消去のために current BG descriptor を再取得しません。`cache clear bg/sprite/visual/all` は visual payload cache に加えて BG/Sprite metadata cache key も無効化しますが、VRAM/BAT/SATB/現在表示中の snapshot は破壊しません。CD-ROM2 VN runtime は現行 catalog path のみを使い、HuCard/非VN template 用の resident asset array fallback は別 runtime の責務です。
- scene pack の各 record は固定長です。command record は 19 byte、message record は 13 byte（`PCE_VN_SCENE_PACK_MESSAGE_SIZE`。末尾に文字色 `text_color` の 9-bit パレット word を u16 で持つ。未指定は `PCE_VN_MESSAGE_COLOR_NONE`=0xffff。mouth slot byte は下位 2bit が slot、上位 6bit が typewriter 前に即時表示する先頭 glyph entry 数）、choice record 6 byte、switch record 5 byte。この値を変える場合は `pce-vn-manager.js` の `encode*Record` / `VN_SCENE_PACK_*_SIZE`、`renderer.js` の `estimateScenePackBytes` 見積り定数、runtime の `scene_pack_read_*` オフセットと `pce_vn_*_t` struct、`vn.h` の `#define ...SIZE` を同時に合わせます。
- scene pack から読む command/message/choice/switch の要素は、CD / asset bank / VDC 転送で MPR が変わる可能性を考え、処理前に stack local にコピーしてから扱います。特に ADPCM は BIOS 呼び出し前に data size、address、divider、loop、play_frames、CD sector を runtime-owned snapshot へ直接コピーし、BIOS 呼び出し後に `pce_editor_adpcm_assets[]` のポインタを再読みに使わないでください。ADPCM meta / snapshot の multi-byte field や `pce_editor_cd_data_ref_t` は `memcpy` や構造体同士の連続 field copy に戻さないでください。llvm-mos が `tii $7c,$6a,#$4` や destination `$0089` のように高位アドレスを落とす転送へ畳むと、WRAM `$207c` / `$2089` ではなく zero page を読んだり書いたりして、ADPCM `data_size` や CD sector が 0 になります。生成ヘッダの `PCE_EDITOR_META_ADPCM_*` offset から scalar decode し、snapshot へは local scalar 経由で書きます。
- VN 変数 storage は 16bit 配列にしないでください。llvm-mos が `vn_variables[index]` を ZP indirect pointer に畳むと、PCE の I/O page 側へ書いて VDC data port 経由で VRAM を壊すことがあります。runtime は `vn_variable_lo[]` / `vn_variable_hi[]` の byte 配列を `VN_BANKED_CODE` の getter/setter で読み書きし、Choice の変数代入や IF/Switch の参照で indirect 16bit store を発生させないようにします。
- CD-ROM2 VN runtime では bank129 / bank130 / bank132 は runtime code / VN data 専用です。`pce_editor_map_asset_bank()` を使う banked asset fallback が必要な場合も、VN runtime では bank131 だけを例外的に使います。
- bank129 から bank130 の helper を呼ぶときは、caller の stack/local への writable pointer を渡さないでください。llvm-mos の banked 呼び出しで pointer が `$0002` などの I/O page に化けると、VDC data port へ書いて VRAM を壊します。CD-DA resume のような banked helper は戻り値か専用 BSS (`cdda_resume_start/end` など) で受け渡します。`VN_OVERLAY_CODE` (bank133) から呼ばれる可能性がある resume 系 helper は、overlay 実行中に bank130 が slot4 から外れるため、bank129 (`VN_BANKED_CODE`) か最小限の bank128 に置きます。
- CD-ROM2 の BG `map_vram.bin` は CD 上では `VN_MAP_WIDTH`(=32)タイル幅のソース行です（旧 64 幅から変更。`PCE_BG_MAP_WIDTH_TILES` と一致）。`mapBase` からファイル全体を一括転送すると、行末が次行左端へ回り込んで本来画像にない縦縞が出ます。runtime は raw `map_vram.bin` を `cd_transfer_scratch` へ1 sectorずつ読んで、各行の `width_tiles` 分だけを `mapBase + command.y * VN_MAP_WIDTH + command.x + row * VN_MAP_WIDTH` へコピーし、左右/上下余白は `clear_screen_map()` のblank tileを残します。
- sprite 描画に必要な cell size、sheet cell 数、pattern base、palette bank は generated `pce_editor_sprite_draw_meta[]` にも小さく出します。CD runtime は共有 `sprite_draw_meta` を持たず、`vn_get_sprite_asset()` から得た descriptor の cell metadata と、SLOT順に割り当てた pattern base / palette bank を slot-local draw metadata へスナップショットして SATB を組みます。animation metadata が sheet 範囲内なら `frame_count: 1` の default でも frame size として使います。旧 default のように frame size 未指定の asset は generator が sheet 全体の 1 frame へ補正します。
- sprite pattern は VRAM の sprite pattern 領域へ転送し、SATB は `VN_SATB_ADDR` (`0x7f00`) を使います。CD-ROM2 でも CD BIOS graphics driver は使わず、System Card の VBlank handler も使いません。通常 frame wait は `pce_cdb_wait_vblank()` の BIOS counter ではなく VDC status の `VDC_FLAG_VBLANK` を guard 付きで直接待ちます。`VN_VDC_CONTROL_BASE` には VDC status latch 用に `VDC_CONTROL_IRQ_VBLANK` を入れますが、HuC6280 側の `IRQ_VDC` は通常 `pce_irq_disable(IRQ_VDC)` で mask します。CD/ADPCM BIOS helper 後も `set_vdc_control()` で System Card の R5 shadow (`$F3/$F4`) を更新し、万一 BIOS helper が shadow を参照しても sprite bit が戻されないようにします。shadow SATB は直接 VRAM へ転送してから `VDC_REG_SATB_START` を維持します。未使用 SATB entry はゼロ化せず `VN_SPRITE_HIDDEN_Y` へ退避します（ゼロ entry も PCE では実 sprite として扱われ、BG の色0部分から pattern 0 が見えることがあります）。同一 slot へ別 sprite asset をロードする pattern upload では、sprite layer を無効化して画面外 SATB を反映し、VRAM 転送後に SATB と sprite layer を再有効化します。`sprite` command はこの一連の表示無効化 → VRAM 転送 → 表示有効化が完了してから次 command へ進みます。
- sprite animation の frame 変化だけでは full refresh を要求しません。full refresh 時に記録した slot ごとの SATB 開始位置と entry 数を使い、既存 layout のまま該当 frame を作り直して SATB の pattern / attr word だけを VRAM へ転送します。位置/表示/flip/animation 切替、spritetext 点滅、screen shake、pattern upload が絡む場合だけ full refresh とし、ADPCM 再生中の animation tick で `clear_sprites()`、palette upload、pattern CD load、64 entry 全転送を繰り返さないでください。ADPCM 再生中でも sprite/spritetext refresh は gate で止めず、口パクを動かすため slot に cache した animation metadata と pattern / attr word 差分更新で per-frame cost を抑えます。
- `background` command も同期 command です。BG 切替は Fade 前提で、`fadeOutFrames` / `fadeInFrames` は `10 / 20 / 30 / 40 / 50 / 60` のプリセットへ正規化します。未指定時は速度3の `30` です。保存済みの旧 `transition: "cut"` は読み込み時に `transition: "fade"` へ移行され、BG の VRAM/BAT 反映と fade 完了まで次 command へ進みません。fade は BG palette bank だけを段階変更し、message UI palette までは暗転させません。
- active message record は `start_message()` で `active_message_state` へコピーし、`tick_active_message()` と auto advance はこの cache を使います。ADPCM 再生中の typewriter tick で `scene_pack_read_message()` の range check / field decode を毎フレーム再実行しないでください。
- `delay_frame()` / `vn_wait_next_vblank()` の VBlank polling は inline asm の tight loop と短い guard で命令数/I/O read 数を抑えます。これは VBlank 数を数える timing 補正ではなく、表示期間中の SATB 更新を避けるための edge wait です。C の 16-bit guard loop や長い polling loop へ戻すと ADPCM 再生中に待ちループ自体が main loop を圧迫し、typewriter/counter が実時間から遅れます。
- VDC memory control は `VN_VDC_MEMORY_CONTROL` (`VDC_CYCLE_4_SLOTS | VDC_BG_SIZE_32_32`) を標準にします。画面は **256x224**（横ドットクロック 5.37MHz の 256 モード）、BAT は **32x32**（=32x30 タイルの表示領域に十分）です。BG size を設定し直す時に sprite cycle bit を落とすと sprite layer が見えなくなるため、`VDC_REG_MEMORY` へはこの定義を使ってください。BAT が 32 幅になったため `VN_MAP_WIDTH`(=32) と `pce-asset-manager.js` の `PCE_BG_MAP_WIDTH_TILES`(=32) は一致させ、BG 画像は **256px(32 タイル)以下**にしてください（`encodePceBackground` が超過時にエラーにします）。
- `pce_editor_vram_copy()` は resident/noinline の共通 VDC blit helper とし、内部で `vn_vdc_irq_lock()` / `vn_vdc_irq_unlock()` を行います。message window clear、`write_map_words()` の BAT 行更新、raw BG/map/font/sprite pattern 転送はすべてこの helper を通すこと。ADPCM/CD external IRQ が MAWR 設定から VRAM data 転送の途中に入ると、数フレームだけ BG/メッセージが壊れて戻るランダムな表示崩れになります。message 開始時の strip clear、速度0の初回全文表示、choice 再描画の一括 glyph draw は、表示中に参照中の 208 tile を連続更新しないよう、message 窓 BAT を `PCE_VN_BLANK_TILE` へ一時退避してから strip tile を更新し、最後に strip BAT へ戻します。Message 表示途中のボタンスキップはこの退避を使わず、現在の glyph cursor から残りを追加描画して既存テキストを消さないでください。Message 用には全画面 display blank や `pending_display_enable` を使わないでください。VN runtime では `pce_vdc_set_copy_word()` を使わず、R5 low byte を保ったまま high byte だけ `VN_VDC_CONTROL_BASE >> 8` へ戻す `vn_vdc_set_copy_word()` を使います。SDK helper は R5 high byte を 0 にして DRAM refresh / VBlank status latch を落とすため、表示崩れや VBlank wait の timeout を再発させます。
- ADPCM / CD-DA の CD BIOS helper から戻った後は、R5 だけでなく `pce_vdc_set_resolution(256, 224, VCE_COLORBURST_ON)`、`VDC_REG_MEMORY`、SATB start、scroll を runtime 標準値へ戻します。System Card BIOS は ADPCM 処理中に水平/垂直 timing register を触ることがあり、display enable だけの復元では画面が上下に二重表示されることがあります。この復元シーケンスも VDC register-select latch を触るため、表示中に復元する場合は `restore_video_after_cdb_call()` 内で VBlank へ寄せてから IRQ mask したまま実行します。ただし display blank 中の復元と `display_enable()` は、blank のまま VBlank を待つと Geargrafx で R5 が `0408` のまま進まないため、先に R5 を通常表示へ戻し、呼び出し側の `delay_frame()` で次 frame を待ちます。sprite layer control は BG を残した状態で VBlank wait 経由にし、screen-shake scroll 更新でも latch 競合が起きるため `set_vdc_control()` と `apply_screen_offset()` 自体も IRQ guard 付きにします。
- CD-DA 再生中の scene pack / BG / sprite / font / ADPCM などの有限 CD data read は、`prepare_cd_data_access()` で CD-DA を一時 pause します。CD-DA と CD data read は同じドライブを使うため同時実行できませんが、BG/sprite の raw visual payload は各 sector read 後に `finish_cd_data_read_before_vram_copy()` で `resume_cdda_after_cd_data_access()` と `map_vn_data()` を済ませてから `cd_transfer_scratch` → VRAM/BAT copy へ入ります。これにより、タイル/マップの VRAM 書き換え中まで CD-DA pause を引きずりません。scene pack など、まとまったロード区間では引き続き `begin_cdda_deferred_resume()` / `end_cdda_deferred_resume()` で再開を遅延します。CD-DA をより途切れさせたくない scene では、BG/Sprite の表示 command 自体を CD-DA 開始前へ寄せてください。
- System Card external IRQ は CD data read / CD-DA pause/play / ADPCM RAM load など BIOS helper の直前だけ有効化し、helper 後は `sync_cd_external_irq_after_bios_call()` で無効化し、VDC IRQ vector も runtime の quiet handler へ戻します。CD unit の enabled/status だけでなく System Card の pending latch `$F2` (`0x20f2`) も `quiet_cd_unit_irqs()` / `vn_cd_irq1_quiet_handler()` で消してください。通常 VN frame では System Card の IRQ mask `$F5` (`0x20f5`) を `PCE_CDB_MASK_IRQ_EXTERNAL` に戻します。Geargrafx では `$F5=0` のまま ADPCM direct playback へ入ると、`CD_ENABLED_IRQS=00` でも BIOS `$E73x-$E82x` VBlank/IRQ dispatcher に張り付き、ADPCM frame counter と PSG service が止まります。ADPCM RAM への CD load は、既定8 sectorまでの `pce_cdb_adpcm_read_from_cd()` chunk に分割し、各チャンクの `cd_transfer_wait()` と ADPCM busy 解除を待ってから次へ進みます。ADPCM busy 解除待ちは CPU 側で回れるため、`VN_ADPCM_BUSY_PSG_POLL_INTERVAL`（既定 `16u`）ごとに `VN_ADPCM_BUSY_PSG_POLL_ITERATIONS`（既定 `192u`）ぶんの VBlank sampler を入れて PSG だけを進めます。sampler が実 VBlank を拾えなかった窓では `VN_ADPCM_BUSY_PSG_FALLBACK_FRAMES`（既定 `1u`）を最小滴下します。さらに各 ADPCM CD read chunk 後は `VN_ADPCM_CD_READ_PSG_COMPENSATION_FRAMES`（既定 `1u`、command 単位）を PSG 専用に足し、BIOS helper 内で観測できない時間を補います。ADPCM RAM に収まる buffered 再生は System Card BIOS の `pce_cdb_adpcm_play()` を使わず、bank129 の direct latch/start helper が address / `0xffff` length / divider を ADPCM hardware へ書いて repeat mode で開始し、同じく bank129 の direct stop helper が PLAY bit を落とします。実データ長を hardware length に入れると通常再生の中間で ADPCM half IRQ (`0x04`) が立つため使いません。true ADPCM streaming は VN runtime から削除済みで、長い message voice は `splitPolicy: "auto"` や低い sample rate で 32767 byte 以下の buffered part に分ける方針にします。VDC R5 の VBlank bit は polling 用に通常有効化し、HuC6280 `IRQ_VDC` は通常 mask します。

## PSG TIMER クレジットドライバ（VN_TIME_SOURCE_TIMER）

`template/template_pce_vn_cd/src/vn_engine_config.h` の `VN_TIME_SOURCE_TIMER` は既定 `1` です。標準 path は HuC6280 TIMER IRQ を通常フレームの実時間源にし、CD/ADPCM BIOS helper 中だけ TIMER を System Card へ返します。BIOS helper の外側で見える待ちは `time_blocked_poll()` が実 VBlank edge として拾い、helper 内で見えない時間は `VN_PSG_CD_TRANSFER_COMPENSATION_FRAMES` の PSG 専用 tick で補います。維持する条件:

- **ISR はクレジット専用**（`vn_psg_timer_irq_handler`）: A/X/Y と MPR0 を退避し、`$1403` ack と `vn_vblank_credit++`（上限 `VN_VBLANK_CREDIT_MAX`）だけを行い **RTI で戻る**。System Card は TIMER ソフトベクタを **JMP でディスパッチ**するため RTS で戻るとスタックがずれて暴走する。ISR 内で PSG レジスタ・MPR2-7・VDC・バンク切替・C ヘルパ呼び出しをしてはならない（過去の IRQ 駆動 PSG がスプライト/BG破壊で撤回された原因）。
- **System Card は CD/ADPCM BIOS ヘルパ実行中に TIMER を自前利用する**。`$20F5` の TIMER dispatch bit を立てたまま CD_READ に入ると BIOS が `$E73x-$E82x` の IRQ ディスパッチャに張り付いて戻らない。このため BIOS プリミティブ（`pce_cdb_cd_read` / `pce_cdb_adpcm_*` / `pce_cdb_cdda_*`）は**マクロで release()-first ラッパに差し替え**てあり、呼び出し前に必ず `vn_psg_timer_release()`（TIQ mask → timer停止 → `$20F5` bit clear の順。逆順は「bit clear なのに TIQ 配送可能」の窓を作り、System Card のデフォルトパスが ack しないためハングする）が走る。再所有は `quiet_cd_unit_irqs()`（毎フレーム/BIOSヘルパ後）の `vn_psg_timer_own()`。own() はリロード書き込みを `vn_timer_owned` フラグでゲートし（毎フレームのリロード再設定はカウンタ位相をリセットして TIQ を永久に飢えさせる）、`$20F5`/IDR ビットは毎回再アサートする。
- **CD シーケンス途中でタイマを再所有しない**。`cd_transfer_wait()`（1 sector / read-slice 待ち）では own() せず、実測 credit を処理した後に `VN_PSG_CD_TRANSFER_COMPENSATION_FRAMES`（既定 `10u`）を **PSG 専用**に `engine_apply_psg_credit()` へ渡します。この credit は `vn_vblank_credit` へ混ぜません。SCSI が settle しきる前にタイマを奪うと次の CD_READ がハングします。
- `$20F5` を書く箇所（`quiet_cd_unit_irqs` / `vn_cd_irq1_quiet_handler`）は `vn_timer_owned` を見て TIMER bit を**単一書き込みで**保存する。クリア→再設定の 2 段書きは禁止（窓でハング）。
- クレジット消費（`vn_consume_vblank_credit`）は owned 時のみ `pce_irq_disable/enable(IRQ_TIMER)` で RMW を保護する（SEI は `vn_vdc_irq_lock` と衝突するため使わない）。
- `VN_TIME_SOURCE_TIMER 1` が現在の標準方式です。fallback を試す場合も release-first BIOS wrapper と「推定 credit は PSG 専用、ADPCM/message timing へ混ぜない」という分離を崩さないでください。

## PSG 補償 tick 調整 TIPS

BG 切替や sprite/font/scene pack の同期 CD ロード中は main loop に戻らないため、PSG は `engine_service_blocking()` / `engine_service()` で cooperative に進めます。標準方式では HuC6280 TIMER IRQ の実 VBlank credit を PSG/ADPCM の frame service に使い、CD/ADPCM BIOS helper の中で見えない待ちだけを PSG 専用 compensation tick で補います。通常フレームは main loop 先頭ではなく `delay_frame()` の VBlank 待ち直後に進め、display 復帰、fade/flash/shake、sprite safe-hide、message/choice window 復帰などで直接 VBlank を待つ箇所も待ち直後に補います。CD/VRAM の大きい転送だけでなく、scene 遷移時の BAT 行クリア、resident BG map fallback、message/choice window の BAT・tile 更新、Full BG 復帰時の font restore、sprite SATB 全転送 / pattern 差分更新の VDC ロック前後でも service を挟みます。PSG pattern は生成時に step/channel 順へ並べ、runtime は cursor で次の event だけを処理します。調整対象は `template/template_pce_vn_cd/src/vn_engine_config.h` の次の定数です。

- `VN_CD_TRANSFER_SETTLE_POLL_ITERATIONS`: CD/ADPCM BIOS helper 後に VBlank edge を拾う cooperative settle poll の上限。既定は `4096u` です。旧実装の `65535u` は各 sector/chunk に大きい人工待ちを足してしまい、初回暗転や BG/sprite/ADPCM 読み込み中の PSG 停滞を悪化させます。
- `VN_CD_RAM_READ_CHUNK_SECTORS`: CD data を直接 RAM bank へ読む経路（bank133 overlay、scene pack cache、bank134/135 PSG pattern）でまとめる sector 数。既定は `2u` です。visual payload cache の page miss-fill と visual-code 側 CD→VRAM fallback は `VN_VISUAL_CACHE_CD_READ_CHUNK_SECTORS`（既定 `4u`）で、LRU page を一時 scratch として最大4 sectorずつ読むため、`cd_transfer_scratch` の 1 sector 制約を受けません。`load_visual_cache_code()` は bank129 予算の都合で 1 sector 読みを維持します。PSG の詰まりをさらに減らしたい場合は chunk を `1u` まで下げられますが、CD command 回数が増えてロード時間は伸びます。
- `PCE_VN_COMMAND_CACHE load`: CD ブラケットをフレーム跨ぎで開いたままにせず、各 BIOS read command は従来通り完了まで待ってから `sync_cd_external_irq_after_bios_call()` で閉じます。その上で command interpreter 側は pending cache state を持ち、BG は tiles/map の 2 substep、sprite/ADPCM/PSG は 1 substep ごとに main loop へ戻ります。`vn_wait_next_vblank()` が毎フレーム `quiet_cd_unit_irqs()` を呼ぶため、フル非同期 CD read へ拡張する場合はこの契約を先に再設計してください。
- `VN_PSG_CD_TRANSFER_COMPENSATION_FRAMES`: 標準方式で使う CD read chunk (`cd_transfer_wait()` / visual cache CD read wait) ごとの PSG 専用補償 tick。既定は `10u` です。ADPCM countdown や message timing には使わないでください。大きくしすぎると、読み込み遅延そのものを隠すだけでテンポが過補正になりやすいため、まず settle poll と RAM read chunk を確認してください。
- `VN_ADPCM_MESSAGE_READ_CHUNK_SECTORS`: message voice の cache miss 時に ADPCM RAM へ読む単位。既定は `8u` です。通常は generator の自動 `Cache Load ADPCM` が直前に入るため、message 可視 glyph 表示時には cache hit します。cache miss 時も seek 支配の BIOS command 回数を減らすため 8 sector までまとめます。
- `VN_ADPCM_PRELOAD_READ_CHUNK_SECTORS`: 明示/自動 `Cache Load ADPCM` で ADPCM RAM へ CD から読む分割単位。既定は `8u` で、各チャンク後に `cd_transfer_wait()` と ADPCM busy 解除を確認してから次のチャンクへ進みます。1 sector に戻すと seek 回数が sector 数に比例し、PSG 停止が大きく悪化します。
- `VN_ADPCM_BUSY_PSG_POLL_INTERVAL`: ADPCM reset/read/stop の busy 解除待ち中に、PSG 専用 VBlank sampler を呼ぶ間隔。既定は `16u` です。小さくすると busy wait 中の PSG は安定しやすくなりますが、voice load 自体は少し伸びます。
- `VN_ADPCM_BUSY_PSG_POLL_ITERATIONS`: ADPCM reset/read/stop の busy 解除待ち中に、間欠的に実行する PSG 専用 VBlank sampler の長さ。既定は `192u` です。CD BIOS helper 内はまだ触れませんが、helper 後の CPU busy wait 区間では PSG の停止感を減らせます。大きくすると voice load 自体は少し伸びます。
- `VN_ADPCM_BUSY_PSG_FALLBACK_FRAMES`: 上記 sampler が実 VBlank を拾えなかったときに、ADPCM busy wait 中へ追加で滴下する PSG 専用 credit。既定は `1u` です。`VN_ADPCM_CD_READ_PSG_COMPENSATION_FRAMES` と違い、ADPCM 転送完了後ではなく busy wait の途中に効きます。大きくすると詰まりは減りますが、ADPCM load 中だけ PSG テンポが先走りやすくなります。
- `VN_ADPCM_CD_READ_PSG_COMPENSATION_FRAMES`: ADPCM RAM への CD read chunk ごとの PSG 専用補償 tick。既定は `1u` です。`VN_PSG_CD_TRANSFER_COMPENSATION_FRAMES` と違い BG/sprite/scene pack には効かせず、ADPCM cache load のテンポ落ちだけを補います。ADPCM countdown や message timing には使わないでください。
- `VN_VISUAL_VRAM_COPY_SLICE_BYTES`: PSG 再生中の BG/Sprite RAM/CD buffer→VRAM copy を分割する byte 数。標準は `16u` です。PSG が鳴っていない場合は `VN_VISUAL_VRAM_COPY_FAST_SLICE_BYTES`（既定 1 sector）までまとめて転送します。CD-DA/PSG の途切れが残る場合はこの値をさらに小さくできますが、総転送時間は伸びます。

調整の目安: PSG が遅く聞こえる場合でも、まず自動 ADPCM preload が効いているか、同期 CD/VRAM 処理の後に service が抜けていないか、`delay_frame()` 内の VBlank 待ち直後 tick と直接 `vn_wait_next_vblank()` する display/sprite/message window 経路の明示 tick が抜けていないかを確認します。catch-up 上限や CD 補償 tick を大きくすると PSG/ADPCM buffer overflow を再発しやすいため最後の手段にしてください。VRAM 転送中の瞬間的な音切れや CD-DA 停止感が残る場合は、まず Geargrafx の PSG register write trace で VBlank gate の service が欠落していないか、MPR6 が bank132 へ戻っているかを確認し、それでも途切れる場合だけ `VN_VISUAL_VRAM_COPY_SLICE_BYTES` を小さくします。通常フレームのテンポ基準は `delay_frame()` なので、BG ロード中だけの補正では触らないでください。大きい PSG pattern は tick 中に MPR6 を bank134/bank135 へ切り替えるため、補償 helper の最後で `map_vn_data()` を戻し、slot4 は入口で保存したバンクへ `vn_slot4_map_bank()` で復元するルール（`VN_MAP_BANK130_FOR_CODE()` の無条件復帰は禁止）を維持してください。
- メッセージフォントは **12x12 グリフ**で、1 行 17 文字 x 4 行（横 12px ピッチ・縦 16px 行ピッチ、メッセージ窓 208x64px を BAT (3,20) に配置）。12px ピッチは 8x8 タイル境界に乗らないため、`font.bin` は先焼きタイルではなく **12x12 1bpp マスク（12 word=24 byte/グリフ）**を持ち、起動時に `upload_font_tiles()` が `PCE_VN_FONT_MASK_VRAM_WORD`（=`(PCE_VN_FONT_TILE_BASE+208+1)*16`）以降の VRAM へストリームします。runtime のグリフコンポジタ（`draw_message_glyph_at` 他）は bank133 overlay (`VN_OVERLAY_CODE`) に置き、resident dispatcher から IRQ を mask した状態で bank133 を slot4 に map して呼び、bank130 へ復帰してから IRQ を戻します。overlay entry は先頭で `map_vn_data()` を呼び、message 開始時に先読みした `.ram_bank132` cache の mask を優先し、cache 外 glyph だけ `pce_vdc_copy_from_vram` で VRAM から読み戻して、メッセージ帯（`PCE_VN_FONT_TILE_BASE` から 208 タイル）の該当 8x8 タイルを read-modify-write で更新します。`vn_glyph_decode()` / `vn_glyph_stride()` は choice と overlay の共有 helper なので `VN_RESIDENT_CODE` に置きます。**全フォント分の常駐ピクセルバッファは持たず、コンポジタを bank128 に置かない**こと。点灯ピクセル=color15（4 プレーン全点灯）なので、タイル先頭 8 word の下位バイトが現在のマスクとして読み戻せます。BG/UI の blank tile は専用の `PCE_VN_BLANK_TILE`（メッセージ帯直後の 1 タイル、起動時にゼロ化）を使い、メッセージ帯タイルとは分離します。
