# 「いしのうらにいる！？」シリーズバイブル

## この文書の目的

この文書は、第2話以降のプロット、シナリオ、PCE VNスクリプトを作るときに、作品とキャラクターを第1話からブレさせないための正本です。

根拠は次の順で扱います。

1. 完成版第1話 `assets/pce-vn-scenes.json`
2. 現行アセット台帳 `assets/pce-assets.json`
3. 当初の企画シート

`assets/pce-vn-scenes - コピー.json` は旧稿なので、口調や表示名の正本にはしません。

## 作品コンセプト

ゲームハード、ゲーム業界、ゲーム文化の話題を、部室の女子たちが好き勝手に語り合います。勝敗や正解を教える作品ではなく、好きなものを語る人がいつの間にか自分の矛盾をさらす様子を笑う作品です。

風刺の対象は、特定企業、特定製品、特定ユーザー層そのものではありません。対象にするのは次のような行動です。

- 推しを持ち上げるために比較対象を雑に扱う
- スペックや売上など、都合のよい数字だけを振り回す
- 自分に都合が悪くなると評価基準を変える
- 本当は遊びたいのに、立場を守るために否定する
- 好きなものの説明が長くなり、相手を置き去りにする

実在企業や製品名は、題材に必要で、事実確認できる場合だけ使います。製品や企業への直接的な悪口ではなく、キャラクターの偏った主張として描き、必要なら別のキャラクターが事実と感情を切り分けます。

## 舞台と部活

「いしのうら部」は、旧校舎のはずれにある、生徒会にも忘れられかけた小さな部室を使っています。

活動内容は次のとおりです。

- ゲームとゲーム機を集める
- 実際に遊ぶ
- ハード、ソフト、業界の話をする
- 機材を修理・改造する
- 中古店やゲーム売り場を調査する
- しばしば意見が衝突してレスバトルになる

部室の機材は部長が直したものが多い一方、ケーブルや機材の整理は雑です。部室は、古いハードと現代機、理屈と感情、知識と素朴な疑問が同じ机に乗る場所です。

## キャラクター

### 部長

| 項目 | 設定 |
| --- | --- |
| ゲーム内話者名 | 部長 |
| 愛称・内部的な呼び方 | ムーちゃん |
| 一人称 | 私 |
| 呼称 | チカくん、レンくん |
| 立場 | レトロゲーム全般が好き。特にPCエンジンを偏愛 |
| 会話上の役割 | 話題を持ち込み、説明し、話を前へ動かす |
| 基本性格 | マイペース、明るい、動じない、細部は雑 |

口調の基準:

- 「ところで」「〜なんだ」「〜だね」「〜だよ」「〜かな」を使う
- 相手を強く否定せず、質問や例えで返す
- レトロゲームの話になると説明が長くなる
- レンの煽りを褒め言葉のように受け取る
- ときどき静かな正論を言うが、本人も偏愛と脱線の当事者である

第1話で確認できる性質:

- PCエンジンの小ささ、HuCARD、CD-ROM2を嬉々として説明する
- 古い機械の手間や修理も遊びの一部として愛している
- 現代のゲームや最新機の価値も認める
- 勝つことより、一緒に遊ぶことへ会話を着地させる
- 知識を披露しているうちに周辺機器やロマンの話まで広げる

ブレ防止:

- 常に正しく、冷静な先生役にはしない
- 知識量で相手を屈服させるだけの人物にしない
- PCエンジン以外を嫌っている人物にしない
- 整理整頓や説明の長さなど、本人にも笑われる欠点を残す

代表的な会話運動:

1. 部長がゲーム機の特徴を説明する
2. 説明に個人的な「かわいい」「ロマン」が混ざる
3. チカが事実と感想を切り分ける
4. 部長が感想も重要だと平然と押し通す

### レン

| 項目 | 設定 |
| --- | --- |
| ゲーム内話者名 | レン |
| 呼ばれ方 | レンちゃん、レンくん |
| 一人称 | うち |
| 呼称 | 部長、チカ |
| 立場 | 現代ハード、特にSIE／PS5寄りの最新機至上主義 |
| 会話上の役割 | 極論と煽りで場を荒らし、レスバを発火させる |
| 基本性格 | 自己中心的、勢い重視、負けず嫌い、素直ではない |

口調の基準:

- 読みやすい軽い似非大阪弁にする
- 「〜や」「〜やろ」「〜へん」「ちゃう」「せや」「なんや」を短文で使う
- 方言を長文全体へ過剰に乗せない
- 大声の否定、言い換え、苦しい理屈でテンポを作る
- 一人称は原則「うち」に統一する。「ウチ」は強い強調が必要な場合だけ

第1話で確認できる性質:

- 「高解像度」「高速ロード」「フレームレート」などを勢いよく並べる
- 用語は使うが、議論の知識や基準は浅く、都合に合わせて変わる
- 紙の帳簿を擁護して「古いものにもよさがある」と自分で証明してしまう
- 古いゲームを否定しながら、実際に遊ぶと夢中になる
- 中古店、限定カラー、周辺機器に弱い
- 負けたり泣きそうになったりして退場しても、誘因があるとすぐ戻る

ブレ防止:

- 本気で他人を傷つける悪役にはしない
- 最新機の知識が完全な嘘ばかりの人物にしない
- 因果応報のあとも孤立させず、「本当はみんなと遊びたい」を残す
- 毎回ただ負けるだけにせず、ときには部長の矛盾を正しく突く
- 下品な罵倒や、読みにくい濃すぎる大阪弁にしない

代表的な会話運動:

1. レンが最新機の優位を断言する
2. 部長かチカが例外や本人の行動を示す
3. レンの発言がブーメランになる
4. レンが「敵情視察」「戦略的撤退」など別名を付けて逃げる

### チカ

| 項目 | 設定 |
| --- | --- |
| ゲーム内話者名 | チカ |
| 一人称 | 私 |
| 呼称 | 部長、レンちゃん |
| 立場 | ゲーム知識の薄い一般人。暇なので部にいる |
| 会話上の役割 | 聞き役、観察役、常識人、ツッコミ、読者の入口 |
| 基本性格 | 控えめ、丁寧、観察力が高い |

口調の基準:

- 基本は「です」「ます」の丁寧語
- 「こんにちはです」「なるほどです」のような少し独特な丁寧さを使える
- 専門用語を知らないときは、そのまま質問する
- 感情的に怒鳴るより、目の前の矛盾や行動を短く指摘する
- ゲーム用語より、弁当箱、片づけ、床を見るなど日常的な例えを使う

第1話で確認できる性質:

- PCエンジンを「白い小さなお弁当箱」と表現する
- 部長の説明から要点を拾い、一般人向けの例えへ変換する
- レンが画面を見ている、手がコントローラへ近づいている、と行動を観察する
- どちらの陣営にも入らず、「どっちも楽しそう」と本質をまとめる
- 最後に短い一言でレスバを終了させる

企画設定にあり、第1話ではまだ前面に出ていない性質:

- 実は非常に裕福
- 本人は金持ちであることを誇示しない
- 金額、購入、所有物の話で一般人離れした金銭感覚が自然に漏れる

この金銭感覚ギャグは、1話に何度も使わず、忘れたころに一度だけ出す程度にします。チカをゲームに詳しい隠れオタクへ変えたり、財力で毎回問題を解決させたりしません。

代表的な会話運動:

1. 二人が専門用語と立場で争う
2. チカが素朴な質問か日常の例えを入れる
3. 二人とも一瞬納得する
4. チカが短い観察で争いそのものを相対化する

## 3人の関係

- 部長とレンは、古い物と新しい物の代理戦争をするが、互いの好きな気持ちは理解している
- 部長はレンの煽りに動じず、遊びへ誘う
- レンは部長へ反発するが、部長が用意したゲームや機材に興味を持つ
- チカはどちらにも肩入れしないが、二人が楽しそうなことは認める
- 3人は勝敗よりも、最後に同じ場所へ行く、同じゲームをする、同じ物を見ることでまとまる

誰か1人を作品の絶対的な正義にしません。

## 1話の基本構成

標準の流れは次のとおりです。

1. **導入**  
   学校、廊下、部室などを見せ、その日の物や話題を提示する。
2. **説明**  
   部長または話題の当事者が特徴を説明し、チカが素朴な質問をする。
3. **最初の2択**  
   チカが対象をどう評価するかを選ぶ。どちらも人格や陣営の固定には使わない。
4. **対立の投入**  
   レンまたはゲストが極論を持ち込み、レスバを始める。
5. **レスバ第1ラウンド**  
   スペック、価格、体験、思い出など異なる評価軸が衝突する。
6. **2回目の2択**  
   チカが誰を止めるか、何を試すかなど、その場の行動を選ぶ。
7. **合流とテーマの整理**  
   分岐は短い会話差分のあと合流し、誰かが相手の価値を一部認める。
8. **現物による因果応報**  
   実際に遊ぶ、接続する、買いに行くなど、口だけでは終わらない展開を置く。
9. **イベントスチル**  
   その話を象徴する見せ場を、話数固有の224×136画像で見せる。原則として全分岐が合流した共通sceneに置く。
10. **チカの一言**  
   最も普通の視点から争いを止める。
11. **タグのオチ**  
    レンのブーメラン、部長の再脱線、金銭感覚のズレなどで軽く締める。

### 分岐のルール

- 2択を2回入れる
- 選択肢はチカの反応または行動として書く
- 選択肢でプレイヤー自身を登場させない
- 片方だけを正解・善として扱わない
- 各分岐は数メッセージから十数メッセージ程度で共通sceneへ合流する
- 長期好感度、恋愛値、正史ルートを作らない
- 分岐で変えるのは直後のボケ、誰が被害を受けるか、オチの言い回し程度にする

## コメディの作り方

優先する笑い:

- 言葉を文字どおり受け取る
- 評価基準が途中で変わる
- 相手に向けた批判が自分へ返る
- 壮大な説明を日用品へ例える
- 否定している本人の手や目が興味を示している
- 大げさな専門用語に対し、現実の小さな行動を指摘する
- もっともらしい総括の直後に、欲望や偏愛が漏れる

避ける笑い:

- 実在企業や開発者への人格攻撃
- 特定ハードの所有者全体を侮辱する表現
- 知識のないチカを見下す笑い
- レンの方言、出身地、女性性そのものを笑う表現
- 恋愛、性的なからかい、いじめ
- 事実でない故障率、売上、性能をナレーションが断定すること
- 誰かが本気で傷ついたまま終わること

## ゲームトピックの事実ルール

現行製品、企業方針、価格、販売数、サービス状況など、時間で変わる題材には「トピック資料」を付けます。

最低限必要な情報:

- 情報の基準日
- 確認済みの事実
- 出典またはユーザーが与えた要約
- まだ不明な点
- 各キャラクターがその事実をどう歪めて解釈するか

ChatGPTは、確認済み事実とキャラクターのポジショントークを混同してはいけません。資料にない具体的な価格、性能、日付、販売数を作らず、不足は一般論へ置き換えるか「要確認」として返します。

## 表記と台詞のスタイル

- ゲーム内の話者名は `部長`、`チカ`、`レン`
- 句点 `。` と読点 `、` は原則使わない
- 間は全角空白、改行、`…`、`！`、`？` で作る
- 1メッセージへ複数の論点を詰め込まない
- 一問一答、短い否定、短い観察を重ねてテンポを作る
- 説明が続く場合でも、チカかレンの反応を数メッセージごとに挟む
- 専門用語を出したら、チカの質問か日常的な言い換えを用意する
- ナレーションは舞台説明、ラウンド表示、締めに限定し、キャラクターの内面を長く説明しない

PCE画面上の具体的な改行・文字数ルールは `chatgpt-authoring-workflow.md` に従います。

## イベントスチルのルール

第2話以降は、シナリオに合わせた新規イベントスチルを各話につき最低3枚作成します。4枚以上に増やす場合も、各画像の物語上の役割を明示します。

標準の3枚:

1. `epNN_001`: その日の題材や現物を印象的に提示する
2. `epNN_002`: レスバまたは因果応報が最高潮になる
3. `epNN_003`: エンディングまたはタグのオチを見せる

この3枚は原則として分岐合流後を含む共通経路へ置き、どの選択でもすべて見られるようにします。追加スチルだけを分岐固有にすることはできます。

- サイズは正確に224×136px
- 通常背景と同じ `background` assetとして使う
- IDは `ep02_001`, `ep02_002` のように話数別の連番にする
- 第1話固有スチルを別の出来事へ使い回さない
- レスバの最高潮、題材となる物の提示、因果応報、エンディングなど、話を象徴する場面を選ぶ
- 原則として分岐合流後の共通sceneへ置き、どの選択でも見られるようにする
- 画像内へ台詞、字幕、ロゴ、吹き出し、ゲームUIを描かない
- 既存立ち絵を参考に、部長、チカ、レンの髪型、服装、色、年齢感を統一する

画風は、グラデーションを抑えたベタ塗りのアニメ塗りとします。

- 輪郭とシルエットを明快にする
- 大きな色面を使う
- 影は少数段階のセル塗りにする
- 柔らかいエアブラシ、写実的な質感、3D調、過剰な光沢を避ける
- 細かすぎる模様やノイズを避け、PCEの16色変換後も読みやすい構図にする

具体的な画像生成・登録手順は `asset-catalog.md` と `chatgpt-authoring-workflow.md` に従います。

## 第1話の既知データ不整合

次の箇所は完成版データに残る誤記であり、キャラクター設定や記述ルールとして学習しません。

1. `ep01_04_battle` の「なんやなんや／また古い箱で 盛り上がっとるんか」はレンの台詞内容だが、`speaker: "チカ"`、チカ音声として登録されている。
2. `ep01_06_01_branch` のレンの台詞「チカ／止める相手を間違えたで！」は、口パク先がチカの `mouthSlot: 1` になっている。
3. 次の2行は17文字を1文字超えているため、今後の改行例には使わない。
   - `昔にしてはがんばったな　いうだけや！`
   - `レンちゃんは　ずっと床を見ていました`

この文書化作業では第1話データ自体を修正しません。

## 新しい話を考えるときのチェック

- その日の題材を1文で説明できるか
- 3人それぞれに異なる評価軸があるか
- 部長とレンの両方に、正しい点と滑稽な点があるか
- チカが説明係ではなく、一般人の質問役に留まっているか
- 2回の選択がチカの反応として成立しているか
- 分岐後に無理なく共通sceneへ戻れるか
- 最後に実際のゲーム、機材、買い物など行動があるか
- 誰かの好きな気持ちを否定して終わっていないか
- 第1話と同じPCエンジン紹介を繰り返していないか
- 各話固有のイベントスチルを最低3枚計画したか
- 必須3枚すべてが全分岐から見られる共通経路にあるか
- イベントスチル以外の新規アセットは必要最小限か
